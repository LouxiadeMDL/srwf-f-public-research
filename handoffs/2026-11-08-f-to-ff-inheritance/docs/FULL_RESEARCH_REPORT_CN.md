# Saturn《超级机器人大战F／F完结篇》：HVM到原生存档继承的全程研究（公开改写版）

**依据节点：** 截至2026年11月8日，整理自《SRWF_HVM_F至FF继承_全程研究与修改报告_20261108》32页底稿、配套只读校验附录、S／EX-S继承审计及历史HVM研究。此稿为独立改写的可共享技术摘要，不复制受版权保护的素材、游戏截图或私人存档。

**主平台与版本：** Saturn F 日文RevB21M为原生代码语义基线；实际通关保存端点为 SSF VB8 G2 DIC1，继承端点为 SSFF T28 DIC1。PSF／PSFF Recompiled是另一种架构的交叉对照，不作为土星原生继承证明。

## 1. 结论及证据层级

同源F最终原生卡通过FF兼容转换、普通记录01载入并在FF中再保存，保留累计389回合、521990资金、隐藏累计7及0109、0113、0114历史位。机师与机体有效身份和关联未丢失，改造保存。独立的新进程FF普通冷读有运行日志、画面和最终卡，但该次冷读尚缺导出的完整WRAM；逐位RAM一致性来自首次FF继承后再保存的状态快照。这仍构成**本镜像和本卡的限定原生继承闭环**，而非任意ROM的兼容证明。

证据等级须分开：原盘与脚本静态字节、人工上下文原函数执行、自然游戏录像/日志、普通保存及冷启动、跨游戏状态消费、改造候选。静态扫描命中、样本数量、清单哈希通过数、模拟器帧数、一次游戏通关是不同维度，不能直接相加。

## 2. 从HVM首项调查到原生业务验证

2026年10月17日前后，HVM01至04以原版F为目标冻结源文件身份，建立74个SCEDATA逻辑目录槽与52个唯一物理场景的关系、14个根引用组、SH-2 Event VM入口0x06004DF0、主分发表0x060B21BC及其256项/158个处理入口。早期四场景的受控加载可以证明来源场景可识别，并不意味着隐藏说得成功；当时root9命中仍为0。

战斗对象不是一张名单。已有原生布局区分：
- actor：74槽，每槽16字节，含地图位置、阵营、行动、关联与场景续行；整备阶段可不持有战场actor。
- pilot缓存：128槽，每槽12字节；缓存存在不必然等于加入我军。
- robot缓存：128槽，每槽30字节；失效槽可能残留旧改造数据。

因此，“看见机师ID”“发现一台同类型机体”“某位变成1”“槽里有四段改造”都不能单独证明最终奖励。需联合有效身份、关联、归属、奖励字段、保存及后续冷读。

HVM04A已有 Original／Auto／Custom、证据门禁、差异预览、CLI和离线页面，能拒绝缺证据的编译意图。后继HVM04B加入事件谓词、分支、有限原处理器核验与存储模型；但软件用例通过不等于通用Auto已生成可自然完成隐藏事件的ROM。正式通用Auto未获整体放行。

## 3. 原版隐藏事件的三类不同业务

### 3.1 蕾西／蕾茜（P09）双路线

同一事件具备两种不能混合的结果：达巴主动说得后，场上已有的四段机体对象转属并保持改造；另一条未说得、击坠后路线则在关后补建一段对象。两条路径均有后继自然样本与保存冷读的限定证据。最终推进到F终局并继承FF的主线，留下的是**一段对象**；先前四段说得证据来自独立对照，不得拼接成这条主线的历史。

P09的场景条件与回调、E2本场状态、CA02一段和四段模板、创建/绑定/登记、等待与返回属于不同环节。原包装会消费行动，空回调不能用来无成本试探资格。E2是本场条件／局部防重复的一部分，并非永久“雷西已加入且四段”证书；重新进入新场景它可以被清掉，同时合法奖励仍存在。

### 3.2 托德（P12）前置历史

P12对应0113；若其历史位写入和长期保存成功，仍需FF中的真实消费者判断是否最终加入。0016是共享流程条件，不是托德独占开关。TSR root0→第四表第23项的候选7E17可在受控VM前缀中执行并置0016；然而测试的相邻等待循环不会顺序进入该候选入口，自然上游仍未完整闭合。P12四处分支读取0016，此外它还影响原生资源根选择；不可在整盘强行设置，也不可将D0.02查询直接改作D0.00写入。

### 3.3 哈曼（P30与P47）两条分支

P30已有自然说得与原生卡差分等限定证据，0109作为前置历史成功进入终局卡及FF继承卡；但此时哈曼尚是敌方，机师池没有其我方有效身份。P47属于另一条候选路线，不能因P30正例就算两条均通过。0109置位、敌方撤退、FF后续招募与奖励各须单独验收。

第34话终局流程的0114从清场前0到结束后1，具有持久性；但没有足够的写入PC及入边证明它是FF合法继承的唯一必要充分开关，仍应标成“终局流程相关候选位”。

## 4. 其他独立事件与历史纠错

- 第18话特定5PP奖励正例具有独立原生卡、库存变化、关后普通保存与两次新进程冷读；该正例和最后通关主线不是同一分支。不能反推第18话所有战术时点的必然奖励。
- FF独立第37话证明另一名可说得角色在不说得并击坠时没有雷西式兜底；“某一人物的兜底”不是通用规则。
- P48双计数与历史累计应按事件单独记账；共享累计不是独立Flag0063。
- 旧研究把TSR+3CDC9跨越两个BE32资源指针拼成了假的“D0 00 00 16”；后继原根表求址已将它排除。孤立的4字节形状不能当作可执行脚本。
- root13相对偏移不得绕开实际root表边界进行猜测；受控root2执行更不能当自然root9命中。
- C1.0A缺目标时旧共享数值可保留，而失败位会改变。软件判断应把found与value拆开，不能以非零旧数值当“查到对象”。
- EB.01属于有序对象对匹配，不等于说得次数。

## 5. 存档格式、持久字段与冷读

本次Yabause原生BKR为32768字节；对应SRM样本65536字节，不能套到任意环境。解码普通进度载荷5632字节、中断载荷12624字节；单条外层另有16字节记录信息。要先解析原生目录、块链及内部校验，再使用解压载荷偏移；不可将“+00B5”误当整卡绝对文件偏移。

Flag池在已解码普通载荷+0094，对应GS+0534的64字节；0109、0113和0114分别位于+00B5/+00B6的指定位。共享累计位于+00A0高四位。保存与读取时还需关注主机RAM、即时state内嵌卡和真正BKR三者可能不是同一时刻。F最终普通冷读有新进程高低RAM作为证据；早期HAMAN_AFTER即时状态内嵌卡仍为此前状态的反例也已保留。

## 6. F最终战役→FF同源原生继承

**输入身份：** F最终BKR SHA256为 c4505e0d426ca504d6871b3ba4987ba7c6fd608ce67a236a69c2c90d1b13c266。FF继承并再保存的BKR SHA256为 5cd23987e83cb8ba4e36a5fcb3ca8a07a287de842d87ef31da0a83eb7ba46c4d。这两个校验值只用于识别已有研究端点；对应文件不公开。

| 项目 | F最终记录01 | FF继承普通01 |
| --- | ---: | ---: |
| 第34话结束后的累计回合 | 389 | 389 |
| 资金 | 521990 | 521990 |
| 共享隐藏累计 | 7 | 7 |
| 0109／0113／0114 | 1／1／1 | 1／1／1 |
| 010B／010C | 0／0 | 0／0 |
| 临时E0／F1 | 1／1 | 0／0 |
| 有效机师、机体身份多重集合 | 56／58 | 同 |

普通载荷差异共22字节：2字节内部校验、9字节三个场景回调重绑、2字节临时条件清零、9字节三条机体当前HP／EN调整。整张32KiB卡共44字节不同。此差分覆盖转换、FF载入、FF再保存的累计效果，不能逐字节都归因于转换提示出现的瞬间。机师池1536字节相同；机体改造及关联保持，但槽8／14的0050和槽82的011F的当前HP／EN发生改变，未证明通用能力刷新算法。

FF回调字段在普通载荷+0084、+0088、+008C，分别被重新绑定到FF场景root4、root5、root8。FF中的场景基址和全局指针单元与F不同；保存历史位可以保留业务资格，但不能把F的旧绝对指针当FF代码或剧本入口。旧中断00虽然外壳名称变为SROBOTFC_00，其旧战场载荷并未相应转成可在FF继续的战斗。验证使用的是普通记录01，不是跨镜像继续F旧即时战场。

普通冷读“日志+画面+卡”以及首次继承并保存后state的RAM检查需分别保留来源。下一项必做是新FF进程正常加载后另外导出低高RAM，重算Flag、对象池和root一致性。

## 7. S高达／EX-S的继承与资源差异

S普通／巡航机体ID为01C0／01C1；EX-S普通／巡航为01C2／01C3。S由捷多Lv30驾驶，EX-S由阿姆罗Lv32驾驶；两机各自的30字节机体记录和12字节关联机师记录继承前后相同。四形态状态及武器菜单读数已得到限定对照，显示数字包含当前存档升级与强化部件，不是未改造基础参数。

四形态合计18个武器挂载位置，对应16条有效基础武器。武器ID从F的04E0–04EF统一映射至FF的0580–058F；13条17字节记录完全相同，3条只有动画选择器2字节不同，其余15字节一致。机体模型号S普通0131→0171、EX-S普通0132→0172，两者实际模型包分别2454、2536字节且整包一致；巡航形态原编号不变，但压缩容器大小有差异，因此尚不能断言解码后模型本体不同。

八个使用组内，火神炮、INCOM、导弹发射器、巡航智能步枪及普通形态智能步枪/光束炮各自相应D_ANIME脚本在本次比较中相同；军刀虽选择器011A不变，但脚本及E_SPR不同；巡航光束炮007A→057F；EX-S反射INCOM057D→0411，脚本同为3064字节而有13字节不同，E_SPR相同。

原受控故障实验出现057D动画白屏停滞，而0411控制路径可以完成伤害并返回地图。但该实验对武器进行了诊断重路由，不能当玩家自然选择反射INCOM的18行正式验收。最后完整逐项影片和矩阵尚未被同一证据集合复核，因此不发布“全部动画通过”结论。

## 8. 修改研究：可做什么、什么不能直接改

1. **限定阈值实验：** R5希罗低HP撤退只保留被定位场景的50→0定点修改与既有回归，不宣称全游戏“禁止撤退”。
2. **AnyFriendly候选：** P09源1097、P12源107E、P30/P47源1017中低九位放宽到1000的研究，仍要求目标、阵营、邻接及玩家主动说得；不是Auto，也未批准跨版整盘应用。
3. **P09 Auto候选：** 先从合法宿主入口出发，选择有效对象，走原成功正文及等待/返回、单次奖励、原生普通保存/冷读；有一个环节不闭合就拒绝构建。
4. **托德：** 保留0016共享控制逻辑，用0113追踪FF后续消费，不能全局强行置位或改共享查询。
5. **哈曼：** 0109记录历史，不能把哈曼无条件转属；P30/P47必须分别满足互斥路线与后续消费者。
6. **机体跨版：** 改写ID与模型/武器引用要同时核验FF端点，绝不能以F补丁偏移、动画编号或缓存字节相等推定完整函数地址相等。
7. **保存与后退：** 每个候选记录输入文件SHA、偏移体系、原字摘要、改动说明、冲突、失败恢复规则、自然验收材料。未满足目标校验、指针边界或硬件对齐要求时，应停止输出候选；不直接改原始备份来制造PASS。

## 9. PS Recompiled桥接的独立研究价值

Windows x64 SRWF_Recompiled分析支持以FF为底座的原生重编译运行时，使用FFMerge虚拟光盘选择性替入F场景槽（FF保留200槽骨架，F槽1–73按条件接入），并通过8段、共3984字节的F语义兼容函数（112重定位）切换上下文。F73交接和脚本返回栈的机器码与受控回放说明这不是只有界面壳；但联合回放仍停在指定EA返回边界，有人工夹具，**PSF→PSFF自然完整战役交接与普通冷读仍待验证**。Saturn BKR→FF自然继承通过，不能替PS重编译项目签署动态验收。
