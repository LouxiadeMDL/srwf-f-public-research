# 2026-09-13: Saturn baseline and direct patch experiment

This update reports fresh local byte checks. It does not distribute game files,
patch payloads, dialogue transcripts, or internal research records.

## Baseline choice

The restoration target remains the original Saturn F Rev A. Rev B is a separate
comparison, and PlayStation values are reference annotations rather than
replacement Saturn values.

The paired expanded Japanese base, F-newplus, and Rev A contain the same 33 ISO
root-file logical contents. This was verified by reading and comparing bytes,
including the main executable and the complete scenario resource. All 33 file
locations differ. The two XA resources were additionally checked across their
allocated Mode 2 sectors for subheader and user-data equality. This is not an
assertion that system areas, gaps, CDDA, or complete disc images are identical.

Input representation and SHA-256:

| Input | Representation | SHA-256 |
| --- | --- | --- |
| Rev A | Original first data-track file | `2b95c5303e0cd7bde472ef0c7082eead89fdecbda5c2e271a4a093440184292a` |
| Rev B | Original first data-track file | `66fe113b6c0d99dc74c9f32e587466877719ecd67a59a7c1adea1b71f5e5707a` |
| F-newplus | Paired single-file raw image | `ef4c7efae701da3a63ee45fe8dfbd39e19e2184bd8e7189b513ff3d6206b9ac2` |

Both A and B scenario resources have 74 decoded index entries. Two existing
decoders agreed on all 148 outputs. Three disputed deployment records agree in
their selected parsed fields across A and B. Five special-event signatures also
match across versions; their handler semantics remain unproven.

Fifteen remaining restoration decisions now preserve Rev A data because the
paired Japanese base contains identical files. This settles which source to
preserve, not how every event opcode behaves. An identical repack is not an
independent semantic reference.

## Guide follow-up

Fourteen additional pages were archived locally. Eleven of the fifteen entries
gained more detailed phase descriptions; four retained earlier evidence without
a stronger new phase reference. Useful distinctions include units already present
at map load, movement during the opening scene, pilot substitution in an existing
unit, and withdrawal before the main force becomes controllable.

One guide conflict remains: the main-force arrival in the DC scenario is described
as turn 3 in a transcript and turn 4 in a detailed play log. No version difference
or resolution is asserted from those descriptions alone.

## F1 direct-application experiment

The original patch contains 311,346 replacement records. Its declared input length
is 584,488,464 bytes and its input CRC is `c8cec05f`. A concatenation of the original
three A track files, preserving their recorded gaps, is 577,079,664 bytes with CRC
`59de701f`. A reimplemented header preflight therefore rejects this representation.
The legacy executable itself was not run; this is not a report of its UI behavior.

A local F1 image was nevertheless generated by applying those original raw offsets
with the length/CRC preflight bypassed. The CUE retains the original track starts
and recorded gaps. Every replacement and unchanged interval was reread and checked.

F1 SHA-256: `ec4444284f20cf717452c0d11c422000a20ed2eb9621a2b75842dd5ed3a43c7b`.

**F1 fails data-structure validation.** A comparison with original sectors finds
2,960 newly inconsistent XA duplicate subheaders. Seventy-five Mode 1 sectors in
the original second-track pregap are pre-existing and are explicitly excluded from
the damage count. The volume descriptor and 33-entry root directory remain
parseable; that does not make the rest of the image valid. No runtime acceptance
or complete EDC/ECC verification is claimed.

As a positive control, applying the same payload to a copy of F-newplus produces
the known unpurified YZZL image exactly:
`e28e0fc61d0d065aa0c2bc66d55ea8033cda92726e339c7184c679274d261ff6`.
The positive control is not F2 and is not a clean translation.

## F2 and F3 readiness

F2 requires a verified set of purified resources on the paired base layout. That
set is not yet available. Choosing the original-data authority did not classify
or undo all gameplay modifications while retaining translation dependencies.

F3 additionally requires every file at its original Rev A location. An earlier
layout probe with unpurified resources damaged 12 of 31 Mode 1 file readbacks;
that probe does not decide whether a future purified resource set will fit.

F2 and F3 were not generated. Remaining work is to bind the modification ledger to
actual writes, verify the restoration operations, rebuild/recompress resources,
and then check file placement, references, sectors, and runtime behavior. No clean
ROM release or complete script-to-screen closure is claimed by this update.
