## 4. 后续已封板的 P / A 成果如何接入

### PS F：P-R1 至 P-R5

本地总封板 ZIP 的 SHA-256 本次匹配：`24ab06eb4ca69d9ee68052bf69717ee7fbe5e2e9c2be24a1162ac76a1627a77b`。

- P-R1：later-text profile 的 token/operand 契约；不同 parser mode 必须分开，F0–F5 不得全局定性。
- P-R2：比较语义事件与两平台各自实现，不继承 opcode 数字、地址或字形编号。
- P-R3：最终公开总结记录 2 个完整真实 CPU trace session、59 token、299 events；本次未重播 trace。
- P-R4：BMESS0 真实结构的变长重排算法验证，包括 100 次源结构 fuzz；**不是变长游戏镜像的运行通过**。
- P-R5：文件持久记录与 F8 动态缓冲区临时 ID 分层；两处静态记录回绑至 SLPS 文件坐标。视觉运行证据不能改写成 CPU source-pointer trace。

### SS F：DIC 交叉测试与 A16

[DIC 交叉报告](2026-09-20-dic-codec-a14-crosscheck.md)记录外部压缩器输出经严格解码 52/52 一致；旧解码器仅 51/52，受影响流少输出 512 字节。适用范围是测试的场景压缩流，不能扩为 BMESS 格式结论。

[A16 报告](2026-09-21-a16-complete-retrospective-and-seal.md)记录 5,507 条 SS→PS 精确关联、113 项累计工程编辑和两模拟器的第一话工程运行验证。它也明确记录第一话 77 行自然中文在现有映射下 **0/77 可直接完整编码**，以及固定布局与字体容量限制。因此“工程链已运行”与“最终中文生产已完成”必须分开。

## 6. 数据库接收顺序

1. `CROSS_GAME_TO_T1.sqlite`：R2 + XREA 审阅 + C 线交接层，非生产游戏数据库。
2. `cross_game_extraction.sqlite` 的 **R2**：8 段/217 token、12 文件比较、151 字段。无 R2 的首次失败轮不能代替。
3. `PSF_SSF_TEXT_SOURCES.sqlite`：来源和字面冲突，不能替代 canonical 码表。
4. `WINKYSOFT_F_ENGINE_KNOWLEDGE_BASE_v0.1.sqlite`：综合主题库及 Closure A；不要用 preserved 构建备份代替封板库。
5. `F_FF_TECH_v0.1.sqlite`：配置、攻略条目、局部修改器证据。
6. `database` 下的专题库：样本、PSCB、文档、SRW4 目录；记录数不能跨库简单相加，因为存在继承与重复。

公开的 `database_catalog.json` 只含库身份与表级计数，不含第三方全文、游戏字节或对白。下载后可生成一个**交接索引数据库**；它不是上述原始研究数据库的全量副本。
