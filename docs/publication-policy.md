# Publication policy

This is a new curated repository with independent history, not a mirror or fork of the private workspace.

| Class | Treatment |
| --- | --- |
| Original general-purpose utilities, synthetic fixtures, rewritten explanations | Publish after source and content review |
| Sizes, hashes and narrowly scoped factual structure observations | Publish with representation, date and evidence limitations |
| Historical notes, tool-derived descriptions, internal status reports | Rewrite; remove paths, private IDs, quotations and payload excerpts |
| ROM/ISO/BIN, disc tracks, commercial assets, fonts, dialogue dumps, saves | Exclude |
| Legacy EXE/DLL, archives, third-party tables and unknown-license code | Exclude pending rights review |
| Private messages, credentials, account configuration, model traces and internal work products | Exclude |

Text files can contain copyrighted payloads too. A safe extension, a passing pattern scan or a .gitignore rule does not establish publication rights. Review every change before adding it. Do not use git add -f to bypass the policy. The manifest is an exact file-and-hash allowlist; it is not a substitute for content review.

Maintenance: edit this public checkout, review the diff, run the synthetic tests and publication check, update PUBLICATION_MANIFEST.json after deliberate review, and commit only the reviewed files. Never merge private history or bulk-copy a research output directory. If a secret is exposed, revoke it and follow GitHub's removal guidance; deleting it in a later commit is insufficient.
