# RevB 数据搬移工具 v0.1.0

日期：2026-10-03。目标：Saturn《超级机器人大战 F》原始 RevB / 21M。

**这是可以执行的物理搬移基础工具，不是 WP 整包移植器，也不是已经通过真实游戏验收的成品。**

本版处理：保持原生文件内容和内部引用不变，在既有 Track 1 内调整选定文件的 ISO9660 LBA、预留文件外空间、更新目录双端序字段、重建受影响的 Mode1 扇区地址及 EDC/ECC，并回读验证。另有完整扇区对齐的传输分块/重组工具。

本版不处理：翻译、压缩编码、内部文本池重排、机体定义生成、菜单功能移植、隐藏事件改写、Track 1 增长、后续轨道移动、模拟器运行。不能因为本版测试通过，就宣称这些功能已经完成。

## 2. 已继承的研究规则

### 2.1 原生版本优先

原始 RevB 目录是 **34 项**，不能沿用 F-newplus/WP 的 33 项数量。原生 Mode1 中 32 项可以逐文件读取；`ADPCM.XA`、`LEVELUP.XA` 为另外两项跨轨资源，不能使用 Mode1 的 offset16/2048 伪造它们的逻辑负载哈希。

本版固定以下三个原生轨道身份，命令行不提供跳过源哈希的开关：

| 轨道 | 字节 | SHA-256 |
|---|---:|---|
| Track 1 | 238711536 | `66fe113b6c0d99dc74c9f32e587466877719ecd67a59a7c1adea1b71f5e5707a` |
| Track 2 | 335919696 | `e7b397d1711dcae23eed94889947d72cf712f7342d3403ab52990fabbc8a4281` |
| Track 3 | 3880800 | `66f03f518c58106976cab1f83c19190103f10f66ccc40ce049c7e08cce58691b` |

测试代码使用独立的 `SYNTHETIC` profile，并强制在回执中保留合成身份。生产 CLI 不接受该 profile。上述哈希是从既有证据继承的输入门槛；不代表本次已经对真实三轨重新计算过哈希。

### 2.2 把三种“迁移”分开

| 层 | 本版支持情况 | 不能越界的内容 |
|---|---|---|
| A. 外部文件位置/LBA 搬移 | 已实现，当前交付做合成测试 | 不更改文件负载、长度、内部指针或脚本 |
| B. 文件内部文本池/记录重排 | 未实现 | 必须另验编码、控制码、共享引用、压缩、解压容量、运行消费者 |
| C. WP 功能或隐藏事件迁入 RevB | 未实现 | 不复制旧偏移、旧 opcode 编号、旧状态约定或整份 WP 资源 |

已有 WP/G1–G7/T0 证据可以作为研究输入；不会自动被解释成新增机体已经具备定义、部署、加入、保存及运行条件。F/FF、PS/SS、RevA/RevB、WP/原生数据域不混用。

### 2.3 保护原生拓扑

`/0`、启动区、卷描述符、路径表和目录位置固定。未选定文件固定。原生内部共享结构（例如 SCEDATA 别名）因整文件内容完全不变而保留；顶层文件存在完全共享 extent 时，本版拒绝搬动该组，而不是默默拆开。

同编号不等于同内容。不会按 WP 的编号删除 RevB 的 SCEDATA 41～45、EFFECT 90/91，也不会把原生 `M_DEAD.BIN` 当作“多出来的私货”。

## 3. 工作流程与迁移顺序

```text
固定原版 CUE + 三轨身份
    ↓
读取 RevB 自己的 PVD、目录、路径表范围和文件负载
    ↓
标记保护区、原生文件区、外部 XA、别名、非零未分配区
    ↓
仅把未占用且用户数据全零的扇区作为候选空隙
    ↓
合并本轮允许腾出的选定文件旧区间
    ↓
原位优先；放不下时在 Track 1 内重新分配
    ↓
冻结 PLAN.json：源哈希 + 请求 + 分配 + 目录 + 计划哈希
    ↓
构建时从真实输入重新计算计划；不信任手改过的计划
    ↓
在独立临时目录复制三轨，以原始输入为所有搬移的读取来源
    ↓
按最终布局计算每个受影响扇区；避免 A→B、B→A 覆盖事故
    ↓
更新目录 LBA 的 little-endian 和 big-endian 两份数值
    ↓
重算改变扇区的 MSF、EDC、ECC；原始坏校验不静默修复
    ↓
逐扇区核对最终配方 + 全目录/全 Mode1 文件回读 + T2/T3 整轨哈希
    ↓
结束前再次核对原始 CUE 和三轨哈希
    ↓
生成静态回执；运行/存档验收仍保持 NOT_RUN
```

**文件分配顺序**为：`SCEDATA.BIN → TSR.BIN → BMESS.BIN → DIC.BIN → FACE.BIN → EFFECT.BIN → C_ROBOT.BIN → KOM.PAC`。只处理用户明确列出的文件，不自动把整张盘重排。该顺序是本工具的工程策略，不冒称游戏原生加载顺序。

**实际验收批次顺序**应为：R0 原样复制；R1 单文件纯搬移；R2 单文件预留空间；R3 多文件联合搬移；R4 分块重组；最后才进入真实模拟器/原生存档验证。内容编辑属于下一份独立合同，不能夹带在 R0～R4 的物理搬移中。

### 空间计算

所有区间使用半开区间 `[start, end)`；分配单位为 2048 字节用户扇区，物理写入单位为 2352 字节原始扇区。

```text
文件实际占用扇区 = ceil(原逻辑长度 / 2048)
预留扇区         = ceil(申请预留字节 / 2048)
分配扇区         = 文件实际占用扇区 + 预留扇区
```

预留空间放在文件 extent 后面，**不增加 ISO 目录里的文件逻辑长度**。旧文件末扇区原有 padding 也保留，不被当作可以随意写入的新增文本区。空间数字来自实际扫描时生成的计划，而不是给一个固定“还有几十 MB”的估计。

零数据空隙只说明字节为零，不能证明没有硬编码 LBA 消费者。计划和回执明确记录这项运行风险。本版不做消费者自动修补，也不把空间成功分配当作 RAM、解压缓冲或加载时序证明。

## 4. 禁止项目与自动拦截

| 禁止项 | 执行措施 |
|---|---|
| 覆盖原文件、覆盖已有输出、输出放入输入目录 | 拒绝；只允许新的独立输出目录 |
| 错版源镜像、混入 A17 候选/WP/RevA/FF | 三轨长度与 SHA-256 固定匹配，否则退出 |
| 把 33 项目录当成 RevB 原生目录 | 生产模式要求 34 项 |
| 搬 `/0`、启动区、PVD、路径表、目录、XA、音轨 | 保护/白名单拒绝 |
| 修改轨道数量、类型、长度、INDEX00/INDEX01、pregap | 严格 CUE 合同及输出对照 |
| 把目录外非零区域自动视为 free space | 不纳入空隙分配 |
| 部分文件重叠、静默拆 alias | 拒绝解析或拒绝搬移 |
| 修改计划并重新填个 SHA 逃过检查 | 构建时重新分配并逐字段比较，仍拒绝 |
| 空间不足时强行把后续轨道往后推 | 报 `NO_CAPACITY_WITHIN_TRACK1`，不扩轨 |
| 顺序覆盖导致循环搬移丢失源数据 | 全部从原始只读输入读取，按最终扇区配方写副本 |
| 修改文本、控制码、内部指针、字模、状态字节 | 本版没有负载导入/编辑接口 |
| 全开 flag、开启坏结局、擅自生成缺失 DLC 定义 | 本版没有这些写入功能 |
| 运行旧 EXE、修改模拟器、写 RAM 作弊 | 工具不启动外部程序或模拟器 |
| 静态通过冒称游戏/存档/硬件通过 | 回执固定分层；运行与存档留 `NOT_RUN` |

说明：本工具防误操作和数据损坏，不是抵抗同机恶意进程/多写入者竞争的事务服务。不要在输入被其他程序写入时运行；普通前后 SHA 校验不是操作系统级全盘锁。

## 5. 标准三轨运行版与云端分析版

标准输出保留：

```text
candidate.cue
Track01.bin   MODE1/2352
Track02.bin   MODE2/2352，内容与原轨完全一致
Track03.bin   AUDIO，内容与原轨完全一致
PLAN.json
ACCEPTANCE.json
NOT_RUNTIME_ACCEPTED.txt
```

CUE 只替换 FILE 名称，其余文本保持原样；Track 2/3 的字节和全盘时间位置均不变。

云端分析版采用 `.part + TRANSFER.json`，不是任意增加 CUE 音轨。默认 16 MiB 上限下，每整块为：

```text
floor(16777216 / 2352) = 7133 sectors
7133 × 2352            = 16776816 bytes
```

按已知原始轨道长度计算：Track1 101493 sectors，需要 15 块；Track2 142823 sectors，需要 21 块；Track3 1650 sectors，需要 1 块；共 37 块。**这是几何计算，不是本次已实际拆分真实三轨的回执。**

每块记录相对字节 offset、长度、SHA-256；重组检查顺序、连续性、完整扇区、块哈希、最终长度和整轨 SHA。缺块、错序、截断、篡改、路径越界、符号链接以及已有输出都会被拒绝。重组后的原始轨道才可以交给原 CUE 使用。

## 6. Windows 使用入口

需要 Python 3.10 或以上；运行工具本身不需要 pip 第三方包。建议把原盘、工具和工作结果放在同级不同目录，例如：

```text
D:\RevB-Migrate\original\  原始 CUE 和三轨
D:\RevB-Migrate\tool\      本工具
D:\RevB-Migrate\work\      事先存在的输出父目录
```

以下路径/预算只是调用示例，不代表真实镜像已验证能容纳该预算。命令在 `tool` 目录中执行；原始 CUE 的文件名按实际名称替换。

### 只读清点

```bat
py -3 revb_migrate.py policy
py -3 revb_migrate.py scan --cue "..\original\original.cue" --out "..\work\SCAN.json"
```

### R0 原样复制，不申请任何搬移

```bat
py -3 revb_migrate.py plan --cue "..\original\original.cue" --out "..\work\R0_PLAN.json"
py -3 revb_migrate.py build --cue "..\original\original.cue" --plan "..\work\R0_PLAN.json" --outdir "..\work\R0"
```

### R1 只搬 SCEDATA，不改内容，也不申请新增容量

```bat
py -3 revb_migrate.py plan --cue "..\original\original.cue" --reserve SCEDATA.BIN=0 --relocate --out "..\work\R1_PLAN.json"
py -3 revb_migrate.py build --cue "..\original\original.cue" --plan "..\work\R1_PLAN.json" --outdir "..\work\R1"
```

### R2 为 SCEDATA 申请文件外 256 KiB 预留（原位优先）

```bat
py -3 revb_migrate.py plan --cue "..\original\original.cue" --reserve SCEDATA.BIN=262144 --out "..\work\R2_PLAN.json"
```

若不足，本版停止，不会擅自扩轨。去掉 `--relocate` 是原位优先；加上该参数是要求所选文件位置确实变化，主要用于纯搬移验证。

### 独立回读已有候选

```bat
py -3 revb_migrate.py verify --cue "..\original\original.cue" --plan "..\work\R1_PLAN.json" --candidate-cue "..\work\R1\candidate.cue"
```

### 传输分块与重组

```bat
py -3 revb_migrate.py split --input "..\original\Track1.bin" --outdir "..\work\T1_parts" --mib 16
py -3 revb_migrate.py join --manifest "..\work\T1_parts\TRANSFER.json" --outdir "..\work\T1_restored"
```

输出路径必须是新路径；再次执行请使用新的批次目录。退出码 `0` 只代表当前命令成功，**不代表运行验收通过**；退出码 `2` 为拦截/输入或结构错误。中间候选在暂存目录中构建并验证，成功后才发布到指定目录。

## 7. 测试和验收结果的分层

本次测试由执行端运行，不把“有测试脚本”写成“已测试”。本工具首轮 36 项测试已在 Linux/Windows 的独立 CI 中执行；完整补充套件由 `ci_test.py` 执行，最终准确数量、失败详情、源码哈希和提交号见随包 `TEST_RESULTS.json`。

关键测试内容包括：原样复制 bit-exact；三文件搬移与预留；原位优先；两次构建哈希一致；原始输入不变；目录外非零区保护；root0/XA 拒绝；错版拒绝；容量溢出拒绝；计划篡改与重新封签篡改拒绝；负载/校验/音轨篡改拒绝；分块重组一致；缺块/乱序/篡改拒绝；独立逐位 EDC 对照；末扇区 padding 保留；循环交换不丢数据；别名保护；部分重叠拒绝；不用生产目录解析器的独立目录/负载回读。

## 9. 来源与复验入口

```bat

```
